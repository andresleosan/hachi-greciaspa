# Firestore Schema

Documento de referencia de las colecciones de Firestore del proyecto `hachi-greciaspa`. Mantenido en sincronía con el código; cualquier cambio de schema debe reflejarse acá y en `firestore.rules`.

Última actualización: 2026-07-31 (Cronos, al definir Fase 2 backlog).

## Convenciones

- Todos los timestamps usan `serverTimestamp()` desde el SDK cliente.
- Los "snapshots" (`serviceName`, `userName`, `price` en `reservas`) se guardan por inmutabilidad histórica: si el servicio cambia de nombre o precio después de creada la reserva, la reserva conserva los valores del momento de creación.

## Colecciones

### `users/{uid}`

Perfil de usuario. Creado en `register()` (`src/services/auth.ts:29`).

| Campo | Tipo | Generated by | Notas |
|---|---|---|---|
| `email` | string | client | bloqueado a mutación por usuario (rule N1) |
| `displayName` | string \| null | client | |
| `role` | 'client' \| 'admin' | client (always 'client' on signup) | admin reasignado por `set-admin.js` |
| `createdAt` | Timestamp | client | `serverTimestamp()` |

**Reglas:** create si auth.uid == uid && role=='client'; read/update propio o admin; update no puede tocar `role` ni `email` para no-admin (regla N1 de `AUDITORIA.md`).

**Custom claims (Auth):** opcional `admin: true` en el token, complementario al role en Firestore. `set-admin.js` lo setea. Las rules de `isAdmin()` loen ambos.

### `reservas/{resId}`

Citas reservadas. Es la colección central de Fase 2.

| Campo | Tipo | Generated by | Notas |
|---|---|---|---|
| `userId` | string | client (auth.uid) | dueño de la reserva |
| `userName` | string \| null | client | snapshot del displayName |
| `userEmail` | string \| null | client | snapshot del email |
| `serviceId` | string | client | FK a `servicios/{docId}` |
| `serviceName` | string | client | snapshot del nombre |
| `price` | number \| null | client | snapshot del precio |
| `date` | string | client | ISO "YYYY-MM-DD" |
| `timeSlot` | string | client | "HH:mm" 24h |
| `durationMin` | number | client | |
| `notes` | string \| null | client | comentarios del cliente |
| `status` | 'pending' \| 'confirmed' \| 'cancelled' \| 'completed' | client/admin | default 'pending' |
| `createdAt` | Timestamp | client | `serverTimestamp()` |
| `createdBy` | 'client' \| 'admin' | client | qué flujo originó la reserva |

**Índices:** compuesto `userId ASC + createdAt DESC` ya en `firestore.indexes.json` (soporta la query de "mis reservas" en `DashboardPage.tsx:39`). Considerar índice `date + timeSlot + serviceId` para ADR-001 (detección de doble-booking).

**Reglas:** ver `firestore.rules:32-40`. T2.4 (ADR-002) relajará `update` para permitir cancelación própria blanca.
